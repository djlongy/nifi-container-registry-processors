# Compact native layer transfer

The full native flow has 22 low-side and 25 high-side processors, plus the webhook listener. Many boxes copy settings, choose an HTTP stage or interpret its result. The compact option groups these metadata decisions in `RouteRegistryTransfer`, while native NiFi still downloads, hashes and uploads the bytes.

`PlanRegistryTransfer` validates the webhook and repository allowlist, resolves immutable digests and emits all job facts: repository, kind, digest, size, media type, destination reference, dependencies, source image, platform and recovery check code. The controller reads a split JSON job once. After downloading, and on the high side, it never reads FlowFile content. Every callback returns `contents=None`.

The low side has eight processors: ReceiveWebhook, PlanTransfer, SplitJobs, RouteTransfer, FetchBlob, HashContent, RetryTransfer and Hold. The high side has four: RouteTransfer, UploadContent, RetryTransfer and Hold. The two diode ports are additional cards. Hold is disabled; its incoming queues retain failures. The original flow remains available for comparison.

The controller handles only metadata HTTP: discovering a repository-scoped token, HEAD checks and starting an upload. FetchBlob and UploadContent stream content with InvokeHTTP. Uploads use an empty POST followed by a native PUT. A manifest is first PUT by digest; only after the registry confirms that digest is the tag PUT. Missing dependencies cause penalised retries and a bulletin with the original image, platform, layer numbers and top-level check code. Native RetryFlowFile bounds network retries to three and dependency retries to 120.

Source authentication is cleared on FetchBlob's callback before HashContent and the diode. Retry, failure and completion paths clear it too. This prevents forwarding the token; it does not erase earlier provenance. A native Authorization attribute is still visible during the HTTP operation. Use the existing ExecuteStreamCommand alternative when tokens must never appear in provenance.

Pick this option when the native canvas is too large but blob streaming must remain in NiFi. Its smaller canvas puts the decision logic in Python rather than separate routing cards. The full native option is easier to follow stage by stage. The existing stdin uploader needs fewer push cards and keeps tokens in process memory, but Python then carries bytes. A controller using only native metadata HTTP is also possible, with more HTTP cards for token handling.

Limits: payload redirects are refused, and Basic credentials are not copied into attributes. This option targets Bearer-auth registries such as the tested Quay pair and anonymous registries. An internal CA can be supplied through SSL Context Service; it adds to Python's system roots. Native InvokeHTTP needs its own trust configuration. Queue byte thresholds must exceed the largest individual blob.

The controller tests cover byte preservation, a 3 GiB callback with content reads forbidden, malformed facts, digest/size failures, foreign upload URLs, HTTP retries, missing dependencies and digest-before-tag ordering. A live production test on 2026-10-14 used GitLab mirror pipeline 12308 and its HTTP 202 webhook. BusyBox 1.36.1 reached high-side Quay with the identical manifest digest `sha256:b7f3d86d6e84fc17718c48bcde1450807faa2d56704205c697b4bd5df7b9e29f`; the 459-byte config and 2,206,402-byte layer were downloaded and verified by digest and size. Failure queues were empty. Multi-GB validation is separate from this small-image proof.
