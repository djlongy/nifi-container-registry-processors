# Compact layer transfer by hand

Use PlanRegistryTransfer and RouteRegistryTransfer 1.5.1 on NiFi 2.12. The low side prepares all job facts before streaming; the high side checks dependencies and commits immutable content before tags.

1. Create `PLANA` with children `PLANALowSide` and `PLANAHighSide`. Bind a parameter context containing `src_url`, `src_user`, sensitive `src_password`, `allowed_repositories`, `platforms` (`all`), `dst_url`, `dst_user`, sensitive `dst_password` and optional `dst_repository`. Registry connection settings belong to this context, not the webhook.
2. In the low child, add **ListenHTTP** `ReceiveWebhook` (Base Path `plana-webhook`, Listening Port `9617`, Return Code `202`, HTTP Headers for Attributes `(?i)(X-.*|Filename|Content-Type)`). Connect success to **PlanRegistryTransfer** `PlanTransfer`, configured from the source parameters. Connect success to **SplitJson** `SplitJobs`, JsonPath `$.jobs`; auto-terminate its original. Connect split to **RouteRegistryTransfer** `RouteTransfer`, Transfer Side `Low`, Registry URL/User/Password from the source parameters. Auto-terminate the Python processors' implicit original relationship.
3. RouteTransfer's http goes to **InvokeHTTP** `FetchBlob`: Method `${registry.http.method}`, URL `${registry.http.url}`, dynamic Authorization `${registry.auth.header}`, Request Body Enabled `false`, Response Redirects Enabled `False`, read/write timeouts `10 mins`. Auto-terminate Original; route Response, Retry, No Retry and Failure back to RouteTransfer. The response returns through the controller to clear authentication before hashing.
4. RouteTransfer's hash goes to **CryptographicHashContent** `HashContent` (SHA-256, Fail When Content Empty `false`), whose success returns to RouteTransfer. Its ready goes to output port `ToDiode`. Its retry goes to **RetryFlowFile** `RetryTransfer`: Retry Attribute `registry.retries`, Maximum Retries `${registry.retry.max}`, Penalize Retries `true`; retry returns to RouteTransfer. Route all failure and exhausted-retry relationships to **UpdateAttribute** `Hold`; auto-terminate Hold's success and keep Hold **DISABLED**. Its input queues hold data; never start Hold.
5. In the high child, connect input port `FromDiode` to **RouteRegistryTransfer** `RouteTransfer` (Transfer Side `High`, destination URL/User/Password and Target Repository from parameters). Its http goes to **InvokeHTTP** `UploadContent`, using the same dynamic method/URL/Authorization properties, Request Body Enabled `true`, Content-Type `${registry.http.media.type}`, Response Body Ignored `true`, Response Header Request Attributes Enabled `true`, prefix `resp.`, redirects `False`, timeouts `10 mins`. Auto-terminate Response; route Original, Retry, No Retry and Failure back to RouteTransfer. Auto-terminate RouteTransfer's ready and implicit original. Its retry uses the same RetryTransfer configuration; failure, unused hash and exhausted retries go to a **DISABLED** Hold.
6. Connect the diode ports through your transfer mechanism. For an estate test only, connect the low output to the high input in the parent group. Set all blob-carrying connection size thresholds above the largest blob (the example uses `20 GB`) and start the processors and diode ports, keeping Hold disabled.
7. Configure GitLab registry-mirror's `MIRROR_WEBHOOK_URL` to the TLS endpoint. Its existing JSON request contains the registry and changed image references/digests. Restrict the sender at the endpoint, acknowledge quickly, and let PlanTransfer validate the registry, allowlist and checksum. Test a new small tag before a multi-GB image.

You know it works when low and high manifest bytes hash to the same digest, every referenced blob exists, and failure queues remain empty. A missing-layer bulletin names the source image and check code; resend through PlanRegistryTransfer's `registry.layers`, `registry.check` and optional `registry.platform` attributes. A separate JSON recovery front end is not supplied here.

Authentication attributes are cleared before hashing and the diode, but earlier provenance can contain the scoped token. Select the stdin-script option if that is unacceptable.
